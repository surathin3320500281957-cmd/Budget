# แดชบอร์ดติดตามสถานะเบิกค่าซ่อม (SLA)

แดชบอร์ดไฟล์เดียว (`dashboard.html`) ใช้ติดตามสถานะการเบิกค่าซ่อม ตั้งแต่ขั้น **ตรวจการจ้าง (ST11)** จนถึง **ขอเบิกค่าจ้าง (ST12)** แยกตามกองและสาขา เปิดใช้งานได้ทันทีโดยดับเบิลคลิกไฟล์ — ไม่ต้องต่ออินเทอร์เน็ต ไม่ต้องติดตั้งโปรแกรมเพิ่ม (Chart.js และ SheetJS ฝังอยู่ในไฟล์แล้ว) เหมาะสำหรับนำขึ้น GitHub Pages หรือแชร์เป็นไฟล์เดียว

---

## 1. โครงสร้างไฟล์ Excel ต้นทาง

ไฟล์ข้อมูลต้นทาง (.xlsx) ต้องมี 4 sheet ตามนี้:

| Sheet | ใช้ทำอะไร |
|---|---|
| **ติดตามสถานะเบิกค่าซ่อม** | ข้อมูลหลักของรอบปัจจุบัน (33 คอลัมน์ เช่น PETITION_NO, RESPONSIBLE_ORG, ST11, ST12, TOTAL_AMOUNT3 ฯลฯ) |
| **BF** | ข้อมูล snapshot ของรอบก่อนหน้า โครงสร้างคอลัมน์เหมือนกับ sheet หลัก ใช้เทียบดูว่ารายการไหนเปลี่ยนสถานะไปจากรอบที่แล้ว |
| **พม_เบิกค่าซ่อม** | ข้อมูลเสริมสำหรับกลุ่ม "ขอเบิกค่าจ้างแล้ว" มีคอลัมน์ **พม-สคล/สตจ** และ **พม-ฝ่าย** ที่ join กับ sheet หลักด้วย เลขที่คำร้อง ↔ PETITION_NO |
| **วันที่ข้อมูล** | 1 แถว มี 2 คอลัมน์: "วันที่ BF" และ "วันที่ Update" ใช้แสดงวันที่ข้อมูลของแต่ละรอบบนแดชบอร์ด |

### การกรองแถวทดสอบ/ไม่นับ
ระบบจะตัดแถวต่อไปนี้ออกจากทั้ง sheet หลักและ sheet BF โดยอัตโนมัติ:
- `BUDGET_YEAR = 9999`
- `USERNAME = "บริษัททดสอบระบบ ปบ"`

## 2. วิธีอัปเดตข้อมูลรอบถัดไป

1. เปิดไฟล์ Excel ต้นทางที่ใช้ทำรอบก่อนหน้า
2. **คัดลอกข้อมูลจาก sheet "ติดตามสถานะเบิกค่าซ่อม" (รอบเก่า) ไปวางแทนที่ sheet "BF"** — นี่คือการทำให้ BF กลายเป็น snapshot ของรอบก่อน
3. นำข้อมูลรอบใหม่ (ทั้งหมด) มาวางแทนที่ sheet **"ติดตามสถานะเบิกค่าซ่อม"**
4. อัปเดต sheet **"พม_เบิกค่าซ่อม"** ให้ตรงกับรายการ "ขอเบิกค่าจ้างแล้ว" ของรอบใหม่ (จำนวนแถวควรเท่ากับจำนวนรายการที่มี ST12 ในรอบใหม่) และกรอกคอลัมน์ **พม-สคล/สตจ** กับ **พม-ฝ่าย** ให้ครบ
5. อัปเดต sheet **"วันที่ข้อมูล"**: ใส่วันที่ของรอบก่อน (BF) และวันที่ของรอบล่าสุด (Update)
6. ส่งไฟล์กลับมาเพื่อสร้างแดชบอร์ดใหม่
   - **ถ้ายังคุยต่อในแชทเดิม**: ส่งมาแค่ไฟล์ Excel ก็พอ
   - **ถ้าเริ่มแชทใหม่ หรือแชทเดิมเงียบไปนาน**: แนบไฟล์ Excel คู่กับ `dashboard.html` ตัวล่าสุด เพื่อให้คงหน้าตาและตัวกรองที่ปรับไว้ ไม่ย้อนกลับไปเป็นแบบเก่า

> ⚠️ ปัจจุบัน (รอบล่าสุด) คอลัมน์ พม-สคล/สตจ และ พม-ฝ่าย ใน sheet พม_เบิกค่าซ่อม ยังว่างอยู่ทั้งหมด ตัวกรองจึงให้ผลเป็น **"ไม่มี"** ทั้ง 219 รายการ พอกรอกข้อมูลจริงเข้ามา ตัวกรอง "มี / ไม่มี" จะแยกรายการได้ทันที

## 3. นิยามตัวชี้วัดหลัก

| รายการ | ความหมาย |
|---|---|
| **จำนวนทั้งหมด** | จำนวนคำร้องซ่อมทั้งหมดในรอบข้อมูล (หลังตัดแถวทดสอบ) |
| **ขอเบิกค่าจ้างแล้ว** | รายการที่มีวันที่ ST12 (ขอเบิกค่าจ้าง) แล้ว |
| **ยังไม่ขอเบิกค่าจ้าง** | รายการที่มี ST11 (ตรวจการจ้าง) แล้ว แต่ยังไม่มี ST12 |
| **วันค้างเบิกค่าจ้าง** | จำนวนวันตั้งแต่ ST11 จนถึงวันที่ข้อมูลล่าสุด (เฉพาะรายการที่ยังไม่ขอเบิก) |
| **วันขอเบิกค่าจ้างแล้ว** | จำนวนวันตั้งแต่ ST12 จนถึงวันที่ข้อมูลล่าสุด (เฉพาะรายการที่ขอเบิกแล้ว) |
| **กอง** | มบ. / ตบ.1 / ตบ.2 — แยกจากคอลัมน์ RESPONSIBLE_ORG |
| **สาขา** | แยกจากคอลัมน์ RESPONSIBLE_ORG (15 สาขา) |
| **พม-สคล/สตจ, พม-ฝ่าย** | ข้อมูลเสริมจาก sheet พม_เบิกค่าซ่อม แสดงเฉพาะรายการ "ขอเบิกค่าจ้างแล้ว" ใช้กรองแบบ มี / ไม่มี |

### สถานะการเปลี่ยนแปลง (เทียบกับรอบก่อน/BF)
เปรียบเทียบสถานะของแต่ละคำร้อง (ผูกด้วย PETITION_NO) ระหว่างรอบปัจจุบันกับ sheet BF:

| ป้ายกำกับ | ความหมาย |
|---|---|
| **ใหม่** | คำร้องที่ไม่มีอยู่ใน BF (เพิ่งเกิดขึ้นในรอบนี้) |
| **ตรวจการจ้าง→ขอเบิกค่าจ้าง** | รอบก่อนยังไม่ขอเบิก รอบนี้ขอเบิกแล้ว (มีความคืบหน้า) |
| **ตรวจการจ้าง→ตรวจการจ้าง** | ยังไม่ขอเบิกทั้งสองรอบ (ยังค้างอยู่) |
| **ขอเบิกค่าจ้าง→ขอเบิกค่าจ้าง** | ขอเบิกแล้วทั้งสองรอบ (เก็บไว้ดูเป็นข้อมูลอ้างอิง) |

> หมายเหตุ: สถานะ "ขอเบิกค่าจ้าง" ถือเป็นสถานะสุดท้าย ไม่มีการย้อนกลับไปเป็น "ตรวจการจ้าง" จึงไม่มีป้ายกำกับสำหรับกรณีนี้

## 4. ส่วนประกอบของแดชบอร์ด

- **แถบตัวกรอง**: กอง, สาขา, ค้นหา (เลขที่คำร้อง/โครงการ/บ้านเลขที่), ช่วงวันค้างเบิก, สถานะการเปลี่ยนแปลง, พม-สคล/สตจ, พม-ฝ่าย และปุ่มล้างตัวกรอง
  - เป็นการกรองแบบ cross-filter: กดเลือกจากการ์ด แท่งอันดับ หรือตัวกรองก็ได้ แต่ละ widget ไม่กรองตัวเอง จึงยังเห็นภาพรวมของมิติตัวเอง แต่กรองมิติอื่นทั้งหมด
  - **ตัวกรอง พม-สคล/สตจ และ พม-ฝ่าย** มีตัวเลือก ทั้งหมด / มี / ไม่มี ("มี" คือกรอกค่าแล้ว "ไม่มี" คือยังว่าง) และจะแสดงเฉพาะรายการที่ขอเบิกค่าจ้างแล้ว เพราะคอลัมน์ พม มีข้อมูลเฉพาะกลุ่มนี้
  - **สีของตัวกรองที่เลือกอยู่**: ช่องจะเปลี่ยนเป็นพื้นสีเข้ม ตัวอักษรขาวตัวหนา และมีป้ายสีเดียวกันขึ้นด้านบน (กด ✕ ที่ป้ายเพื่อเอาออก) สีของแต่ละตัวกรองดังนี้

    | ตัวกรอง | สี |
    |---|---|
    | กอง | ส้ม |
    | สาขา | เขียวอมฟ้า |
    | ค้นหา | น้ำเงิน |
    | ช่วงวันค้างเบิก | ฟ้า |
    | สถานะการเปลี่ยนแปลง | น้ำตาลส้ม |
    | พม-สคล/สตจ | ม่วง |
    | พม-ฝ่าย | ชมพูเข้ม |
    | สถานะ (เลือกจากการ์ด) | เขียวเมื่อเลือก "ขอเบิกแล้ว" แดงเมื่อเลือก "ยังไม่ขอเบิก" |
- **การ์ด KPI 3 ใบ**: รายการทั้งหมด (สีน้ำเงิน) / ขอเบิกค่าจ้างแล้ว (สีเขียว) / ยังไม่ขอเบิกค่าจ้าง (สีแดง)
  - ทุกใบแสดงจำนวน มูลค่ารวม และ % ของทั้งหมด ใบ "ยังไม่ขอเบิก" แสดงจำนวนที่ค้างเกิน 60 วันด้วย
  - กดการ์ดเพื่อกรองตามสถานะ การ์ดที่เลือกอยู่จะมีกรอบรอบทั้งใบ
- **ตัวเลือกเมตริก**: สลับกราฟอันดับระหว่าง จำนวนรายการ กับ มูลค่า (บาท)
- **อันดับตามกอง / ตามสาขา**: แท่งเรียงจากมากไปน้อย สีไล่ตามลำดับ (ส้ม เหลือง เขียวอ่อน เขียว เขียวฟ้า ฟ้า …) ตัวเลขอยู่ชิดขวา กดแท่งเพื่อกรองได้
- **โดนัทสถานะขอเบิกค่าจ้าง**: สัดส่วน เบิกแล้ว / ยังไม่เบิก แสดงจำนวนและ % บนกราฟ และยอดรวมตรงกลาง ไม่ถูกกรองด้วยการ์ดสถานะ จึงเห็นภาพรวมเสมอ แต่ยังกรองตามตัวกรองอื่น
- **ตารางสรุปรายกอง/สาขา**: ตารางรายงาน (ไม่ใช่ตัวกรอง) จัดกลุ่มตามกอง มีแถวรวมย่อยต่อกองพร้อมสีประจำกอง และแถวรวมทั้งหมดท้ายตาราง หัวตารางโทนม่วง สลับสีเข้ม/อ่อนทีละคอลัมน์
- **ตารางรายละเอียด**: เรียงลำดับได้ทุกคอลัมน์ (คลิกหัวตาราง) หัวตารางโทนน้ำเงิน สลับสีเข้ม/อ่อนทีละคอลัมน์ มีคอลัมน์ดังนี้
  - กอง, สาขา, โครงการ, บ้านเลขที่, เลขที่คำร้อง, จำนวนเงิน
  - ตรวจการจ้าง (ST11), ขอเบิกค่าจ้าง (ST12), สถานะ
  - พม-สคล/สตจ, พม-ฝ่าย, การเปลี่ยนแปลง
  - วันค้างเบิกค่าจ้าง, วันขอเบิกค่าจ้างแล้ว
- **ปุ่ม Export**: ตารางสรุปและตารางรายละเอียดมีปุ่ม PDF และ Excel แยกกัน export เฉพาะข้อมูลของตารางนั้นตามตัวกรองปัจจุบัน
- **กล่องข้อสังเกตข้อมูล**: เตือนเรื่องการบันทึกวันที่ย้อนหลัง ควร monitor รายการที่ค้างนานผิดปกติ

## 5. หมายเหตุด้านเทคนิค

- ฟอนต์: ใช้ Sarabun / Noto Sans Thai ถ้าเครื่องมีติดตั้ง ถ้าไม่มีจะใช้ฟอนต์ไทยของระบบแทน (ไม่โหลดฟอนต์จากอินเทอร์เน็ต เพื่อให้ยังใช้งานออฟไลน์ได้)
- ไฟล์เดียวจบ (`dashboard.html`) — HTML, CSS, JavaScript, Chart.js, SheetJS ฝังรวมอยู่ในไฟล์เดียวกันหมด ไม่พึ่งพา CDN ภายนอก ใช้งานได้แม้ออฟไลน์หรืออยู่หลัง firewall องค์กร
- ปีพุทธศักราชในไฟล์ต้นทาง (เช่น sheet วันที่ข้อมูล) จะถูกแปลงเป็น ค.ศ. อัตโนมัติตอนประมวลผล แต่หน้าจอแสดงผลเป็น พ.ศ. ตามรูปแบบการแสดงวันที่ไทย
- ก่อนส่งมอบทุกครั้งมีการตรวจสอบ: ไม่มีอักขระเพี้ยน (U+FFFD), ตรวจ syntax ของ JavaScript, จำลองการ render ด้วย headless browser เทียบจำนวน/ค่าที่ถูกต้องกับข้อมูลจริง, ทดสอบการกรอง/เรียงลำดับ/ปุ่ม Export
