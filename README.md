# SLA Dashboard — ติดตามงานขอเบิกค่าจ้าง

Dashboard แบบ interactive (ไฟล์ HTML เดียว รันได้แบบ offline) สำหรับติดตามคำร้องเบิกค่าซ่อมที่ "ตรวจการจ้าง" (ST11) แล้วแต่ยัง "ไม่ได้ขอเบิกค่าจ้าง" (ST12) — พร้อมเปรียบเทียบความเปลี่ยนแปลงกับข้อมูลรอบก่อนหน้า

**ไฟล์ที่ส่งมอบ:** `dashboard.html` — เปิดได้ทันทีด้วย double-click หรือ deploy ขึ้น static hosting (เช่น GitHub Pages) ได้เลย ไม่ต้องมี build step หรือ server ใดๆ

---

## 1. ข้อมูลต้นทางและวิธี Update รอบถัดไป

Dashboard สร้างจากไฟล์ Excel ที่มี **3 sheet**:

| Sheet | ความหมาย |
|---|---|
| `ติดตามสถานะเบิกค่าซ่อม` | ข้อมูล **ปัจจุบัน** (รอบล่าสุด) — ใช้เป็นข้อมูลหลักของ dashboard ทั้งหมด |
| `BF` | ข้อมูล **รอบก่อนหน้า** (snapshot ครั้งที่แล้ว) — ใช้เทียบหาความเปลี่ยนแปลงเท่านั้น |
| `วันที่ข้อมูล` | ระบุวันที่ของข้อมูลทั้งสองรอบ 2 คอลัมน์: **วันที่ BF** (วันที่ของ snapshot รอบก่อน) และ **วันที่ Update** (วันที่ของข้อมูลรอบปัจจุบัน) — ใช้เป็นวันอ้างอิงคำนวณ "จำนวนวันค้าง" ทั้งหมดในหน้า Dashboard |

ทั้งสาม sheet ต้องมีโครงสร้างคอลัมน์ตรงตามนี้ (2 sheet แรก join กันด้วย `PETITION_NO`) — `วันที่ข้อมูล` มี 1 แถวข้อมูล คอลัมน์ A = วันที่ BF, คอลัมน์ B = วันที่ Update

**เมื่อจะ update รอบถัดไป:**
1. เอาไฟล์ข้อมูล "ปัจจุบัน" ของรอบนี้ (ที่กำลังจะกลายเป็นข้อมูลเก่า) ไปวางเป็น sheet `BF`
2. Export ข้อมูลล่าสุดจากระบบต้นทางมาเป็น sheet `ติดตามสถานะเบิกค่าซ่อม`
3. อัปเดต sheet `วันที่ข้อมูล`: วันที่ BF = วันที่ของข้อมูลรอบก่อน (ที่เพิ่งย้ายไปเป็น BF), วันที่ Update = วันที่ของข้อมูลรอบใหม่
4. ส่งไฟล์ Excel (3 sheet) ให้ Claude เพื่อ regenerate `dashboard.html` ใหม่

> การเปรียบเทียบทั้งหมดเป็นแบบ **"รอบต่อรอบ" (period-over-period)** เทียบแค่ 2 จุดเวลาล่าสุดเท่านั้น ไม่ได้เก็บประวัติย้อนหลังหลายรอบ
>
> **หมายเหตุปฏิทิน:** วันที่ในสอง sheet นี้บันทึกเป็นเลขปีพุทธศักราช (เช่น 2569) แต่เก็บในเซลล์แบบตรงตัว (ไม่ได้แปลงเป็น ค.ศ. โดย Excel) — ระบบจะแปลงให้อัตโนมัติ (ลบ 543 จากปีที่มากกว่า 2400) ก่อนใช้คำนวณ

### การเตรียมข้อมูลก่อนใช้งาน (ทำอัตโนมัติทุกครั้งที่ regenerate)
- ตัดแถวข้อมูลทดสอบระบบออก (`BUDGET_YEAR = 9999`, `USERNAME = "บริษัททดสอบระบบ ปบ"`)
- แยก `RESPONSIBLE_ORG` เป็น 2 ระดับ: **กอง** (มบ. / ตบ.1 / ตบ.2 — มาจากส่วนท้ายของชื่อหน่วยงาน) และ **สาขา** (15 สาขา)
- แปลงวันที่ ST11/ST12 จากข้อความเป็นวันที่จริง

## 2. นิยามตัวชี้วัดหลัก

| คำ | ความหมาย |
|---|---|
| **ตรวจการจ้าง (ST11)** | ขั้นตอนที่ยืนยันว่างานซ่อมเสร็จ พร้อมเข้าสู่กระบวนการเบิกจ่าย |
| **ขอเบิกค่าจ้าง (ST12)** | ขั้นตอนที่ยื่นขอเบิกเงินค่าจ้างแล้ว — ถือว่า "เสร็จสิ้น" ในบริบทของ dashboard นี้ |
| **วันค้างเบิกค่าจ้าง** | จำนวนวันจาก ST11 ถึง **วันที่ Update** (จาก sheet วันที่ข้อมูล) — นับเฉพาะรายการที่ยังไม่ถึง ST12 |
| **วันขอเบิกค่าจ้างแล้ว** | จำนวนวันจาก ST12 ถึงวันที่ Update — นับเฉพาะรายการที่ขอเบิกแล้ว |
| **ช่วงวันค้าง** | จัดกลุ่ม "วันค้างเบิกค่าจ้าง" เป็น 5 ช่วง: 0-15 / 16-30 / 31-45 / 46-60 / เกิน 60 วัน |

### การเปลี่ยนแปลงจากครั้งก่อน (เทียบกับ sheet BF)
เทียบสถานะ ST12 ของแต่ละ `PETITION_NO` ระหว่างรอบนี้กับรอบก่อน ได้ 4 กลุ่ม (หมวด "ขอเบิกค่าจ้าง → ตรวจการจ้าง" ไม่ถูกจำลองไว้ เพราะไม่เกิดขึ้นจริงในทางธุรกิจ — ขอเบิกค่าจ้างถือเป็นสถานะสุดท้าย):

| กลุ่ม | ความหมาย |
|---|---|
| ตรวจการจ้าง → ขอเบิกค่าจ้าง | **คืบหน้ารอบนี้** — เพิ่งขอเบิกค่าจ้างในช่วงที่ผ่านมา |
| ตรวจการจ้าง → ตรวจการจ้าง | ยังค้างเหมือนเดิม ไม่มีความเคลื่อนไหว |
| ขอเบิกค่าจ้าง → ขอเบิกค่าจ้าง | ขอเบิกไปแล้วตั้งแต่รอบก่อน ไม่มีอะไรเปลี่ยน (เก็บไว้ดูเป็นข้อมูลอ้างอิง) |
| ใหม่ | เลขที่คำร้องนี้ไม่มีอยู่ใน sheet BF (เป็นคำร้องใหม่ของรอบนี้) |

## 3. ส่วนประกอบของ Dashboard

- **Card สรุป 3 ใบ**: รายการทั้งหมด / ขอเบิกค่าจ้างแล้ว / ยังไม่ขอเบิกค่าจ้าง (แสดงทั้งจำนวนและมูลค่า คลิกเพื่อกรองได้)
- **กราฟจัดอันดับ (กอง / สาขา)**: แนวนอนแบบ ranking bar สลับเมตริกได้ (จำนวนรายการ / จำนวนค้าง / วันค้างเฉลี่ย / มูลค่ารวม) คลิกแท่งเพื่อกรอง
- **กราฟโดนัท**: สัดส่วนขอเบิกแล้ว vs ยังไม่ขอเบิก
- **ตัวกรอง**: กอง, สาขา, ค้นหา (เลขคำร้อง/โครงการ), ช่วงวันค้าง, **การเปลี่ยนแปลงจากครั้งก่อน**
- **ตารางสรุปตามกอง/สาขา**: จำนวน + มูลค่า แยกขอเบิกแล้ว/ยังไม่ขอเบิก
- **ตารางรายละเอียด**: กอง, สาขา, โครงการ, บ้านเลขที่, เลขที่คำร้อง, สถานะ, **การเปลี่ยนแปลง**, วันค้างเบิกค่าจ้าง, วันขอเบิกค่าจ้างแล้ว
- **Export แยกอิสระ 2 ชุด**: เหนือตารางสรุป และเหนือตารางรายละเอียด แต่ละชุดมีปุ่ม Export PDF (เปิดแท็บพิมพ์) และ Export Excel (.xlsx) ของตารางนั้นๆ ตามตัวกรองที่ใช้อยู่ขณะนั้น

ทุก filter ทำงานแบบ **cross-filter**: คลิกที่กราฟ/แถวตารางเพื่อกรองส่วนอื่นทั้งหมด โดยกราฟ/ตารางที่ถูกคลิกเองจะไม่ถูกกรอง (ยังเห็นภาพรวมครบ พร้อมไฮไลต์ตัวที่เลือก)

## 4. ข้อควรระวังด้านคุณภาพข้อมูล

พบว่าในงานที่ขอเบิกค่าจ้างแล้ว มีบางส่วน (~38% ของรอบแรกที่ตรวจสอบ) ที่วันที่ ST12 ถูกบันทึกไว้ **ก่อน** วันที่ ST11 ซึ่งผิดลำดับเวลา น่าจะมาจากการบันทึกข้อมูลย้อนหลังในระบบต้นทาง — Dashboard จึงเลี่ยงใช้ "ระยะเวลา ST11→ST12" เป็นตัวชี้วัด SLA หลัก และใช้ "วันค้างนับถึงวันนี้" แทน (มีหมายเหตุแสดงในหน้า dashboard ด้วย)

## 5. หมายเหตุทางเทคนิค

- ไฟล์เดียวจบ (self-contained): ไลบรารี Chart.js และ SheetJS (xlsx) ถูกฝังไว้ในไฟล์ ไม่โหลดจาก CDN ภายนอก จึงใช้งานได้แม้อยู่หลังไฟร์วอลล์องค์กรหรือไม่มีอินเทอร์เน็ต
- ข้อมูลทั้งหมดฝังอยู่ใน `<script type="application/json">` ภายในไฟล์ — เป็น snapshot ณ เวลาที่สร้างไฟล์ ไม่ได้ดึงข้อมูลสดจากที่ไหน
- ปุ่ม Export Excel ใช้ downloads capability ของ claude.ai เมื่อเปิดผ่านลิงก์ artifact และ fallback เป็นการดาวน์โหลดผ่านเบราว์เซอร์ปกติเมื่อเปิดเป็นไฟล์ทั่วไป (เช่นบน GitHub Pages)
- รองรับ dark mode ตามการตั้งค่าเบราว์เซอร์/ระบบของผู้ใช้
